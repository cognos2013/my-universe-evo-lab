# 我的宇宙：构建与实现方案

- 版本：0.2（2026-09-06 增补世界模型与场景路线）
- 日期：2026-09-05
- 状态：设计基线；生态与背景原型进展见阶段验收，生成式逼真场景为后续规划
- 后续规格：[详细设计方案](02-详细设计.md)

## 1. 愿景与能力边界

构建一个可回溯、可分叉、可干预的宇宙演化实验室。用户拥有上帝视角，能够进入宇宙、恒星系、行星、生态区、聚落及个体尺度，观察物质、生命、智能与文明的发展；既可以只观察，也可以改变条件并比较结果。

以科学模型构成运行基础，以哲学典籍提供观察与实验视角，以游戏式交互支持操作。

系统不逐粒子复制宇宙，不声称能够从大爆炸精确计算出今天的人类社会，也不预测唯一未来。生命起源仍存在未解决问题；从无机环境到生命、从生命到智慧的过程需要明确的模型假设。复杂性和智能都不是必然结局。

## 2. 三种运行模式

| 模式 | 用户体验 | 实现与真实性约定 |
| --- | --- | --- |
| 历史重建 | 进入宇宙早期、原始地球、生命演化和文明史 | 以观测、地质、化石和历史资料为锚点，补全内容标明为模型生成 |
| 自由演化 | 调整初始条件，观察另一条世界历史 | 规则与随机过程共同决定结果，允许没有生命、停滞或灭绝 |
| 地球未来 | 从现实数据快照出发，改变能源、生态、技术和制度条件 | 运行多种情景、参数和随机种子，展示条件性结果与不确定性 |

历史重建允许抵达今天的地球；自由演化不保证重现人类。强制加载的历史事件必须显示为历史锚点。未来情景的运行频率不能直接称为现实发生概率。

## 3. 六层演化系统

| 层级 | 核心状态 | 初期模型 |
| --- | --- | --- |
| 宇宙 | 年龄、尺度因子、密度场 | 背景演化与统计结构生成 |
| 星系与恒星 | 质量、位置、年龄、元素丰度 | 简化引力与恒星演化模型或查表 |
| 行星 | 轨道、大气、温度、水、地形、碳循环 | 球面网格与简化气候、地质模型 |
| 生命 | 种群、遗传性状、代谢、生态关系 | 个体与种群模型结合 |
| 智能与社会 | 记忆、技能、关系、语言、群体规范 | 有限认知智能体与文化传播 |
| 文明 | 人口、生产、能源、技术、制度、贸易 | 智能体与资源流量模型结合 |

层间通过物质、能量和信息交换发生反馈：恒星辐射影响气候，气候影响生态和粮食，粮食影响社会，社会的排放与土地利用再影响生态和气候。

宇宙早期形成轻元素，恒星与星系的形成相互交织，恒星演化进一步提供行星与生命所需的元素。避免把宇宙过程简化成互不重叠的游戏关卡。

## 4. 生命演化

生命使用可遗传的性状，包括代谢效率、环境耐受、繁殖、寿命、移动、感知、防御、合作、学习和记忆。通过实际资源获取、存活和繁殖决定后代数量，不设置统一的高级程度分数。

第一版在预定义性状空间中进行遗传变异与选择；后续研究允许新身体结构、代谢组合和行为结构出现的开放式演化。自然选择之外还应逐步纳入遗传漂变、基因交流和生态反馈。

生命起源设置独立模块，可选择历史初始化、人工播种或不同前生命化学假设。未知的起源概率必须以实验参数呈现。

提供地球演化导览，通过历史快照进入关键阶段，再从任意阶段创建自由分支。不得把预设阶段切换宣称为自发演化。

## 5. 智能与文明

个体具有有限知识、记忆、技能和生活需要。社会通过分工、交换、学习、冲突与规则形成逐步发展。

重点实现资源积累、知识传播、合作冲突、规则执行和环境反馈。技术需要前置知识、材料、能源与试验投入，允许失败与失传；制度通过资源使用权、分配规则和执行机制表示。

不预设唯一优越的文明形态。观察人口健康、生态状态、资源分配、知识保存和灾后恢复能力。

大语言模型用于人物对话、事件解释和编年史，可为少量关键角色提出行动。所有行动必须经引擎验证，不能通过生成叙述凭空创建资源、知识或事件。

## 6. 典籍参考与设计转译

每个思想模块记录“原始观点—设计转译—变量—实验—限制”。以下均为产品设计转译，不宣称典籍提供了对应数学方程。

| 参考 | 观察视角 | 实现 |
| --- | --- | --- |
| 《物种起源》与现代演化理论 | 遗传变异、选择、共同祖先 | 谱系、适应、分化、灭绝 |
| 《物演通论》 | 递弱代偿、依赖关系 | 依赖网络、维护成本、脆弱环节与恢复能力 |
| 《易经》及《易传》 | 变化、关系、时位、条件转换 | 状态趋势、临界条件、反馈；可选文化解释界面 |
| 佛经中的缘起相关经文 | 条件依存、无常、欲求与行为 | 因果依赖图、结构形成消散、行为反馈 |

《物演通论》模块允许检验复杂性、依赖和脆弱性的关系，也允许冗余和协作提高稳定性，不把复杂必然脆弱写成结论。

《易经》模块可提供卦象式解释，但映射必须公开，不能承担科学预测功能。

佛经模块以条件依存启发观察，不把工程依赖图等同于佛教全部义理，不把宗教概念未经验证地写成物理规则。

后续补充热力学、生态学、控制论、制度研究；默认思想观察模块不修改引擎，改变机制时必须创建明确标记的实验规则集。

## 7. 上帝视角与干预

六项核心工具：时空导航、时间轴、对象观察器、干预面板、世界分支树和原因解释器。

时间轴采用宇宙年代总览与局部精细时间。支持暂停、加速、跳转历史锚点和恢复存档。

从同一时刻建立多条分支，如保留撞击、移除撞击、改变撞击规模、改变撞击前生态多样性，再比较后果。

干预分为改变世界事物和改变世界规则。修改引力、代谢成本等属于规则分支。只观察时不得因打开某个视角而改变演化。

## 8. 时间、尺度与存档

使用分层时间推进，宇宙、生态、社会各自采用合适步长，重要事件触发同步与步长缩短。

使用分层精度，远处对象以统计状态表示，关注区域启用细节计算。新增细节必须遵守总量与历史约束，镜头缩放不得制造资源。

回溯通过恢复快照与事件重放完成，不倒算耗散和随机过程。世界存档保存父分支、时间、模型版本、规则参数、随机状态、各层快照、数据版本和干预日志。

未来时间点须先运行才能显示；远期推演允许后台计算。固定版本和环境下追求可重复，跨平台数值计算采用规定误差容限。

统一单位并记录物质和能量收支，开放系统显式记录输入输出。

## 9. 现实地球数据与验证

首批接入人口、经济、能源、土地利用、气候与生态数据。每项保存观测日期、来源、空间范围和不确定性，区分观测、估计与模拟。

“某年地球”不意味着所有数据均更新到当日。数据更新产生新的现实基线，不静默改写已运行分支。

从较早年份初始化，使用未参与拟合的后续区间做验证；开展参数敏感性、多种子和模型对照。未来视图展示条件性范围，不只展示单一曲线。

## 10. 技术路线

| 部分 | 建议 |
| --- | --- |
| UI | TypeScript，时间轴、对象检查、分支对比 |
| 三维 | Three.js，验证 WebGPU 与兼容路径 |
| 初始核心 | 独立 TypeScript 模块，在 Worker 中运行 |
| 性能热点 | 经性能分析后迁移到 Rust / WebAssembly |
| 模型校准 | Python |
| 存档 | 首版本地 IndexedDB，后续服务器快照与事件存储 |
| 批量实验 | 后台队列，运行不同种子和参数 |
| AI | 基于事件日志的解释和受约束行动提案 |

可以评估 REBOUND 等局部轨道计算工具，但不将轨道工具视为完整宇宙模型。先验证反馈、干预和可追溯性，再扩大计算规模。

## 11. 分阶段实施

以下为采用简化模型和现成素材的小型团队估算，不包含科研级真实性研究，尚未经开发速度验证。

| 阶段 | 时间估算 | 成果 |
| --- | --- | --- |
| 规则与数据规格 | 2—3 周 | 模型边界、状态、单位和交互原型 |
| 单行星生命沙盒 | 6—10 周 | 环境、资源、繁殖、变异、灭绝、存档分叉 |
| 智能与文明 | 再增加 8—12 周 | 聚落、生产、知识、制度与反馈 |
| 宇宙演化导览 | 再增加 6—10 周 | 多尺度展示、历史锚点、局部模型 |
| 现实与未来 | 再增加 8—12 周 | 数据快照、历史验证、情景集合 |
| 持续深化 | 长期 | 前生命化学、开放式演化、气候文明研究 |

完整简化产品按约 8—12 个月量级规划；个人开发应进一步缩小模块数量。详细设计优先落实第一版，其余阶段列出扩展合同。

## 12. 首个交付：一颗行星，两条历史

一颗具有海陆与简化气候的星球，播种原始生命，观察遗传与生态变化；复制某个时刻，只改变一个条件，并排比较两条历史。

同时提供宇宙总时间轴作为可浏览的背景与历史入口，不把背景动画冒充全尺度数值模拟。

验收关注：环境改变确实影响生存繁殖；种群可共存、分化或灭绝；反馈可解释；存档可重放；分支可比较；视角不改变世界；数据、推断与假设可区分。

## 14. 世界模型与逼真场景方向

新增空间场景生成路线，借鉴 World Labs 的持久三维世界、空间上下文和可控镜头思路。资料核对与详细开发任务见 [世界模型与逼真场景开发方案](14-世界模型与逼真场景开发方案.md)。官方研究和产品能力与本项目设计推断在该文中分别标注。

产品目标是在“宇宙 → 行星 → 区域”之外增加可进入的局部环境：第一次生成后保存空间资产，反复进入与回溯时保持同一场景；以后逐步覆盖更多地貌和模型支持的生态、文明环境。

采用“模拟真值 → 空间语义布局 → 外观生成与渲染”的分工。模拟引擎决定物质、生命和事件，生成模型在约束内补足视觉细节。场景漂亮不等于历史真实，未被观测或计算的细节标为生成补全；外观中出现的对象不自动加入生态或文明状态。

优先使用现有 Three.js 建立程序化局部样板，再验证外部 SPZ/网格资产，最后评估可替换的生成服务。增加场景合同、资产缓存、坐标标定、历史版本和跨视角验收；不从零训练同规模世界模型，不将未开放研究能力作为交付前提。

首个视觉交付为一块可漫游的代表性岩岸，不声称覆盖整个区域的真实地形。资金与性能预算在原型后确定。当前仅完成方案归档，没有接入 World Labs 服务或生成新的逼真场景。
