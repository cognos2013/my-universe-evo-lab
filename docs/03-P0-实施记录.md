## 2. 运行方式

要求 Node.js 24 或更新的兼容版本。核心无第三方运行依赖；开发依赖为 TypeScript 与 Node 类型声明，版本由 package-lock.json 固定。

```bash
npm ci --ignore-scripts
npm run check
npm run scenarios
npm run scenarios -- show two-lineages
npm run validate
```

导出与验证一个场景文件（目标文件必须尚不存在）：

```bash
npm run scenarios -- export two-lineages /tmp/my-universe-scenario.json
npm run validate -- /tmp/my-universe-scenario.json
```

CLI 失败返回非零退出码；导出默认拒绝覆盖已有文件。场景包携带类型、格式版本、内容和 SHA-256 校验和。校验和用于检测损坏，不是数字签名或可信来源证明。

## 3. 参数和单位决策

字段名包含单位，温度 K，面积 m²，时间 s，能量 J，入射通量 W/m²。MU 是模型物质，不等于真实碳、氮或磷质量。

| 参数 | 当前默认 | 解释 |
| --- | --- | --- |
| 时间步 | 86,400 s | 一个模型日；尚未验证数值稳定性 |
| 模板网格 | 320 单元 | P1 的首次球面初始化目标 |
| 单元上限 | 5,120 | 合同支持的规模上限 |
| 默认队列预算 | 10,000 | 后续性能基准前的预算 |
| 初始温度 | 288 K | 人工场景初值 |
| 每单元营养 | 1,000 MU | 无回收模板为 20 MU |
| 个体结构物质 | 1 MU | 暂定常量 |
| 个体出生能量 | 10 J | 数字生命设计值，不是实测微生物参数 |
| 两种最适温度 | 283 K、298 K | 观察环境改变下性状差异的实验起点 |
| 变异概率 | 0.01 | 无回收模板关闭突变；算法在 P2 实现 |

参数域属于输入保护和模型边界，不保证域内所有组合均稳定或适宜生命。环境积分、性状代价与真实数据校准在后续阶段验证。局部播种材料是否充足，必须在 P1 生成空间分配后检查；仅通过场景 schema 不代表初始化一定成功。

## 4. 确定性协议

协议 ID：`xoshiro128ss-sha256-v1`。

1. 用规范 JSON 编码 algorithm、seed、channel、entityId、tick，按键名排序。
2. 使用 UTF-8 编码和 SHA-256。
3. 取摘要前 128 位，按四段八位十六进制读为 uint32。
4. 极端情况下四字全零，将首字设为 1。
5. 按 xoshiro128** 1.1 的转移计算下一个 uint32。
6. 除以 2^32 得到 [0,1) 的数值。

种子按原始字符串编码，用户界面不得静默修改。随机坐标不包含 branchId、镜头、系统时间。通道建议使用 environment、birth、death、mutation、migration 等稳定 ID；调用方须为每次逻辑事件分配稳定坐标，并避免每次抽样都重建同一流。

多流模式可按事件坐标重建后在一次事件内消费；持久流则必须保存快照。P0 WorldState 暂含一个主流快照。后续若引入跨 tick 的多个持久流，必须升级状态合同保存完整流表，不能只保存主流。

采用 xoshiro128** 的 32 位版本便于浏览器整数运算。未采用密码学随机，也未提供统计独立性的数学保证。共同随机坐标便于分支对照，分叉后实体变化仍需多种子重复实验。

实现参考 [David Blackman 与 Sebastiano Vigna 的原始代码](https://prng.di.unimi.it/xoshiro128starstar.c)。原实现声明公共领域并允许使用、复制、修改和分发；本项目保留出处与许可说明，见 [第三方说明](04-第三方说明.md)。

## 5. 序列化边界

- 格式 `my-universe-p0`，包版本 1；数据 schema 1.0.0；引擎 0.1.0。
- Float64Array 与 Uint32Array 使用显式类型标签和数值数组；导入前验证，避免整数截断或回绕。
- 严格拒绝未知字段、不兼容版本、损坏校验和、不一致的规则摘要、非有限数值、非法引用与收支不平衡。
- 场景文件上限 1 MB，状态文件上限 50 MB；限制递归深度与数组长度。
- 状态验证要求父谱系在数组和时间上先于子谱系；网格邻接互相对应，无自连接或重复边。
- 静态物质账误差容限为 `1e-8 + 1e-10 × max(预期总量, 实际总量)`，不是未来积分器的误差预算。
- 哈希固定对象字段顺序，数组顺序仍有意义。`-0` 规范化为 `0`。

这是 P0 交换格式，不是 P4 完整恢复系统。待执行命令、持续强迫、完整时间轴、分支块存储、IndexedDB 事务和历史重放尚未实现，加入时必须升级存档格式。当前只验证状态与随机流的往返，不声称实现了演化历史重放。
